# Vehicle Inventory

A full-stack vehicle inventory application built with an Express REST API, React, PostgreSQL,
Prisma, and Tailwind CSS. The project is being developed with visible
Red–Green–Refactor commits.

## Current status

Milestone 1 establishes the TypeScript monorepo, database model, Supabase-compatible Prisma
configuration, local PostgreSQL fallback, automated quality checks, and CI.

## Architecture

```text
React SPA -> Express routes -> controllers -> services -> repositories -> Prisma -> PostgreSQL
```

The production database can be hosted by Supabase, but authentication and authorization remain
inside the Express API. Supabase Auth is intentionally not used because the assignment requires
registration, password hashing, JWT login, and role checks to be demonstrated in the backend.

## Prerequisites

- Node.js 20 or newer
- npm 10 or newer
- A Supabase project, or Docker for the local PostgreSQL fallback

## Setup

```bash
npm install
cp backend/.env.example backend/.env
npm run prisma:generate --workspace backend
npm run dev
```

On PowerShell, copy the environment file with:

```powershell
Copy-Item backend/.env.example backend/.env
```

### Supabase connection

Create a Supabase PostgreSQL project and copy its connection strings from **Connect** in the
dashboard.

- `DATABASE_URL`: the Supavisor transaction-mode connection on port `6543` for runtime traffic.
- `DIRECT_URL`: the Supavisor session-mode connection on port `5432` for Prisma migrations.

Use a dedicated database password and URL-encode special password characters. Never expose either
connection string to the React application. Prisma 7 reads the migration connection from
`backend/prisma.config.ts`; database URLs no longer belong in `schema.prisma`.

### Local PostgreSQL fallback

```bash
docker compose up -d
npm run prisma:migrate:dev --workspace backend -- --name init
```

The matching local connection strings are already documented in `backend/.env.example`.

## Database decisions

- Prices use PostgreSQL `DECIMAL(12,2)`.
- Vehicle quantity is a non-negative integer enforced in the database.
- Email addresses are unique and will be normalized by the application.
- UUIDs are generated by PostgreSQL.
- Public registration will only create `USER` accounts.
- An `ADMIN` account will be seeded from environment variables in the authentication milestone.
- Supabase Data API access is not required; the Express API is the only public data boundary.

## Documented assumptions

- Create, update, delete, and restock operations are admin-only.
- Purchase and restock accept a positive integer quantity.
- Zero-stock vehicles remain visible but cannot be purchased.
- Insufficient stock returns `409 Conflict`.
- Search filters are combinable, case-insensitive, and validate price ranges.
- `PUT` will perform a complete vehicle replacement.
